## Проверка и баллы

S получает отдельный балл за типы и сигнатуры и балл за поведение. P требует точный вывод, свободное объяснение и причинную трассировку; автоматический балл за причины опирается на проверяемые состояния объектов. Свободный текст сохраняется для содержательного разбора и не оценивается по ключевым словам. Есть вариант повторения с другими значениями.

В D сначала сохраняется объяснение и набор затронутых правил, затем открывается редактирование. Баллы: причинный набор правил, компилируемое исправление, тесты. Произвольный текст не получает автоматической семантической оценки. Исходные небезопасные фрагменты не исполняются без исправления.

A/B получают долю баллов за пройденные контракты. C компилируется как настоящая программа с stdin, отдельным stderr и проверкой числовых результатов с допуском. Для проверки исключения задаётся интерфейс `int run_stereolab(std::istream&, std::ostream&)`; его объявление находится в `solution.hpp`, определение — в `solution.cpp`, точка входа — в `main.cpp`.

Компиляция без тестов не начисляет баллы. Прогресс использует последнюю проверку новых заданий. Теория не добавляет баллы StereoLab. Полный автоматический зачёт требует всех заданий и критических условий; незавершённый C явно отмечается в итогах. Автоматическая проверка не оценивает исчерпывающе стиль и качество свободных объяснений.

## Связь исходников

A2 и A3 проверяются автономно с минимальными закрытыми тестовыми зависимостями. Это урезанные интерфейсы, которые не содержат полного решения предыдущих заданий.

B/C используют реальные сохранённые исходники ученика A1–A3 и B1–B2. При отсутствии реализации проверка сообщает ID зависимости. В сборке доступны заголовки `StereoSample.hpp`, `ChannelMix.hpp`, `AudioBlock.hpp`, `StereoIO.hpp`, `StereoPipeline.hpp`. Собственные объявления размещаются в `solution.hpp`, отдельные определения — в `solution.cpp`; функции, полностью определённые в заголовке вне класса, должны соблюдать правило одного определения (например, быть `inline`). Все файлы снимка компилируются вместе с зависимостями. Хеши зависимостей сохраняются в результате попытки.

Ключи Q/P/D, полные тесты и контрольные реализации не отправляются в клиентский каталог. Объяснения Q/P выдаются после отправки ответа. Контрольные реализации в `tests/fixtures/day01_v2/` предназначены только для проверки инфраструктуры во временном профиле; в пользовательские решения они не копируются.

## Чистая версия

В проекте оставлена только текущая практика StereoLab. Ученические ответы, черновики, попытки и прогресс не входят в Git. При первом запуске создаются начальные файлы без решений; исходные дефектные фрагменты D остаются условиями упражнений.

Новый пустой профиль получает отдельный идентификатор. Браузер удаляет черновики предыдущего профиля, чтобы они не восстановили старые ответы. Теория и Дни 2–5 сохраняют свои учебные материалы.
