# Лекция № 4: списки, STL-контейнеры и сложность

Открыть [лекцию № 4](http://127.0.0.1:8765/#/theory/4/overview). В боковой панели она находится в модуле «Списки и STL».

Полный исходный пакет сохранён в `content/lecture-04/`, включая `README_FIRST.md`, инструкции, теорию, три main и руководство локального запуска. Все 7 исходных файлов сохранены побайтно; контрольные суммы — в `source.sha256.json`. Авторский текст разбит на введение, четыре большие главы и заключение без сокращений, изменения примеров или направлений связей в схемах.

После глав доступны четыре составных закрепления с исправлением коротких фрагментов, схемами и аргументированным объяснением. Они не требуют реализации больших классов. Код и ответы ученик пишет самостоятельно; готовых ответов нет.

Во вкладке «Практика» — ровно три проекта:

| Проект | Файл реализации ученика | Авторская проверка |
|---|---|---|
| ForwardChain<T> | `forward_chain.hpp` | `MAIN_FORWARD_CHAIN.cpp` |
| BidirectionalList<T> | `bidirectional_list.hpp` | `MAIN_BIDIRECTIONAL_LIST.cpp` |
| CollectionLab | `collection_operations.hpp` | `MAIN_COLLECTION_LAB.cpp` |

Первые два проекта используют собственные узлы. CollectionLab специально использует `vector`, `list`, `deque`; ограничение STL из официальной ЛР № 1 к этому независимому проекту не относится. Условия содержат полный контракт API, семантику, этапы, дополнительные граничные проверки и вопросы для защиты. Стартовые файлы содержат только комментарии.

Проверочные main можно открыть в проекте через «Проверочный main» или выбрать во вкладке «Локальная проверка». Доступны копирование и скачивание с исходными именами. В ZIP проекта включаются текущие собственные файлы ученика и соответствующий неизменённый main.

Сохраните выбранный main рядом со своим .hpp и выполните, например, в PowerShell:

```powershell
g++ -std=c++17 -Wall -Wextra -Wconversion -Wpedantic -Werror MAIN_FORWARD_CHAIN.cpp -o check_forward.exe
.\check_forward.exe
```

Для других проектов замените имя MAIN; каждый собирается отдельно. В Linux/macOS запуск — `./check_forward`. Для Clang используйте `clang++`. В Visual Studio создайте C++17-проект с одним выбранным MAIN. Не определяйте `NDEBUG`: он отключает assert. Определения методов шаблонов должны быть доступны в .hpp или подключаемом .tpp.

Ожидаемый вывод соответственно: `ForwardChain: basic checks passed`, `BidirectionalList: basic checks passed`, `CollectionLab: basic checks passed`. Базовый main — первичный контроль; он не заменяет проверку граничных случаев и памяти. Команды дополнительной сборки с санитайзерами доступны на странице каждого из первых двух проектов при поддержке компилятора.

Чтение, закрепления и проекты сохраняются отдельно в существующем профиле. Этапы реализации, проблемы компиляции, замечания ревью, граничные сценарии, статус памяти и подсказки фиксируются самим учеником. «Сохранить ход работы» сохраняет незавершённую попытку; итоговая отметка требует завершённых этапов, подтверждённых критериев и собственного обоснования сложности. Наличие ошибок памяти препятствует положительной отметке. Просмотр или скачивание main не завершает задание.

Техническая интеграция переиспользует `LecturePack` и существующие API. Новые условия — в `days/day-04-lists/lectures/lecture-04/`; генератор — `tools/prepare_lecture04.py`. Метаданные первых трёх лекций, их учебные материалы, исходники и записи прогресса сохраняются. Сайт не импортирует и не вызывает C++-компилятор.

Проверки разработки: `npm run build`, `npm test`, `npm run test:lecture04-browser`. Дополнительный `npm run test:lecture-mains` проверяет только синтаксис/API исходных main по объявлениям, без создания готовых реализаций и без выполнения кода ученика.
