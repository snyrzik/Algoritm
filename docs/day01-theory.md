## Самостоятельные закрепления

| Глава | ID | Класс | Независимые сценарии |

| 1 | d1-l1-c01 | ScoreCounter | 7 |

| 4 | d1-l1-c04 | ClockTime | 11 |

Кнопка «Открыть редактор» в конце каждой главы открывает отдельную проверку на существующем экране задания. Файлы находятся в `student/day-01/d1-l1-cXX/`. Сохранение, компилятор, история, снимки и подсказки используют штатный механизм платформы. Стартеры содержат только комментарии, решения не публикуются.

Для ScoreCounter и Duration в `test_adapter.hpp` выбираются имена ваших методов чтения/изменения через указатели на методы. Значения points/add/seconds — настройки адаптера, их можно изменить. Готовых методов в адаптере нет; тип результата, const и ссылочная семантика проверяются компилятором. В FixedHistory константное чтение допускает как значение int, так и const int&, поскольку оба соответствуют условию; изменяемый доступ обязан возвращать int&.

Для ClockTime проверяется строгий формат HH:MM с двумя цифрами в каждой части. Протокол в редакторе явно описывает допустимые ошибки конструктора, ведущие пробелы и сохранение настроек потока. Смысл письменного объяснения и качество проектирования по-прежнему требуют самостоятельного разбора.

Прогресс четырёх закреплений показан отдельно в лекции. Их прохождение не засчитывает никакое исходное задание. Базовый каталог содержит прежние 292 задания (52 в Дне 1); адресный доступ к четырём новым проверкам расширяет каталог до 296. CLI `--day 1` сохраняет прежний набор основной практики.

## Подготовка и проверка добавления

Все новые условия и C++-тесты хранятся в репозитории. При необходимости `npm run prepare:theory` пересоздаёт только четыре новых комплекта и недостающие файлы этих решений, не перезаписывая существующие файлы ученика. Основные задания и остальные дни этот скрипт не читает для генерации и не изменяет.

```powershell
npm run build
npm test
npm run test:theory-browser
```

Новые проверки инфраструктуры сверяют контрольные суммы 763 прежних файлов курса (с учётом системных переводов строк), байтовую контрольную сумму исходного Markdown, полноту текста, отдельный прогресс, адаптеры редактора и реальную компиляцию новых тестовых программ. Браузерная проверка сравнивает отрендеренный текст и каждый пример со всем исходным материалом, проверяет главы, ссылки на темы, переходы к четырём редакторам, обе темы и мобильную вёрстку.
