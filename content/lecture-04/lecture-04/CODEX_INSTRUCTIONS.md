## Проект 1. `ForwardChain<T>` — полноценный односвязный список

**Цель:** применить указатели, структуру узла, деструктор, глубокое копирование, `const`, исключения, поиск/удаление и разворот цепочки.

Не нужно создавать десять маленьких классов. Реализуется один связный контейнер.

### Обязательный публичный интерфейс

Контракт вызовов должен соответствовать готовому проверочному файлу `MAIN_FORWARD_CHAIN.cpp`:

```cpp
#include <cstddef>

template <typename T>
class ForwardChain {
public:
    ForwardChain();
    ForwardChain(const ForwardChain& other);
    ForwardChain& operator=(const ForwardChain& other);
    ~ForwardChain();

    bool empty() const;
    std::size_t size() const;
    const T& front() const;

    void push_front(const T& value);
    T pop_front();
    bool contains(const T& value) const;
    bool erase_first(const T& value);
    void reverse();
    void clear();
};
```

Это **описание контракта API, а не готовое решение**. На странице задания можно показывать требования словами, а сигнатуры спрятать в отдельную вкладку «Сверить интерфейс после самостоятельной попытки»; однако для совместимости с `main` ученик должен иметь возможность открыть точный контракт.

### Семантика

- Изначально список пуст.
- `push_front` ставит новый элемент первым.
- `front` возвращает ссылку на первый элемент; на пустом списке бросает `std::out_of_range`.
- `pop_front` удаляет первый элемент и возвращает его значение; на пустом списке бросает `std::out_of_range`.
- `contains` ищет первое совпадение, используя `operator==` типа `T`.
- `erase_first` удаляет **только первое** совпадение; возвращает `false`, если значение отсутствует.
- `reverse` изменяет порядок узлов **на месте** и не выделяет массив с копиями элементов. Время `O(N)`, дополнительная память `O(1)`.
- `clear` освобождает все узлы; повторный вызов допустим.
- Копирование означает независимое **глубокое копирование всей цепочки** с сохранением порядка элементов.
- Самоприсваивание безопасно.
- Инвариант `size()` всегда совпадает с количеством достижимых узлов.

### Этапы проекта

1. Пустой список, `Node`, создание/удаление узлов.
2. Вставка в голову, чтение, удаление из головы.
3. Поиск значения и удаление первого совпадения.
4. Разворот списка без дополнительных узлов и массива.
5. Правило трёх, независимость копий, самоприсваивание.
6. Локальные проверки, дополнительные собственные тесты, объяснение сложности.

### Дополнительные строгие проверки

- Пустой список.
- Единственный узел.
- Дубликаты в начале и середине.
- Отсутствующее значение.
- Разворот пустого и одноэлементного списка.
- Копирование пустого списка.
- Копирование списка с `std::string`.
- Самоприсваивание.
- Уничтожение без утечек.
- Поведение, когда копирование элемента `T` бросает исключение: сохранять корректность ресурса и не оставлять недоступные узлы (можно рассмотреть как расширенный уровень проверки).

### Вопросы для защиты

Почему `push_front` занимает `O(1)`? Почему `erase_first` обычно требует `O(N)`? Почему нельзя просто копировать `head`? Почему `reverse` можно сделать без выделения новых узлов? Чем отличается ссылка на указатель от указателя по значению?

## Проект 2. `BidirectionalList<T>` — двусвязный список

**Цель:** научиться поддерживать взаимные ссылки, оба конца и размер списка при любой последовательности операций.

### Обязательный интерфейс

```cpp
#include <cstddef>

template <typename T>
class BidirectionalList {
public:
    BidirectionalList();
    BidirectionalList(const BidirectionalList& other);
    BidirectionalList& operator=(const BidirectionalList& other);
    ~BidirectionalList();

    bool empty() const;
    std::size_t size() const;
    const T& front() const;
    const T& back() const;
    T& at(std::size_t index);
    const T& at(std::size_t index) const;
    const T& at_from_back(std::size_t offset) const;

    void push_front(const T& value);
    void push_back(const T& value);
    T pop_front();
    T pop_back();
    void insert_before(std::size_t index, const T& value);
    void erase_at(std::size_t index);
    void clear();
};
```

### Семантика

- В пустом списке и `head`, и `tail` равны `nullptr`.
- `front`/`back`, `pop_front`/`pop_back` для пустого списка бросают `std::out_of_range`.
- `at(index)` допустим для `0 <= index < size()`; иначе `std::out_of_range`.
- `at_from_back(0)` — последний элемент; `at_from_back(size()-1)` — первый.
- `push_front`, `push_back`, `pop_front`, `pop_back` должны быть `O(1)` по числу изменяемых связей (без учёта стоимости создания/копирования `T`).
- `insert_before(index, value)` допустим для `0 <= index <= size()`. При `index == size()` добавить в конец. В противном случае вставить перед элементом с индексом `index`.
- `erase_at(index)` удаляет элемент с индексом `index`; индекс за диапазоном вызывает исключение.
- `at` и `insert_before` по индексу обычно требуют `O(N)` из-за поиска позиции, даже если изменение связей `O(1)`.
- Копирование глубокое, порядок сохраняется; самоприсваивание корректно.
- После каждого изменения соблюдены взаимные связи `next`/`prev`, состояние `head/tail`, корректный размер.

### Этапы

1. Пустой список и одноэлементное состояние.
2. Вставка в оба конца и удаление с обоих концов.
3. Чтение по прямому и обратному индексам.
4. Вставка перед произвольной позицией, включая обе границы.
5. Удаление начала, середины и конца.
6. Копирование, присваивание и очистка.
7. Анализ ошибок указателей, собственные тесты, объяснение сложности.

### Обязательные проверки

Проверить последовательность из разных вставок и удалений, а не отдельные изолированные вызовы; после каждого изменения сверить `front`, `back`, `at`, `at_from_back`, `size`, `empty`. Отдельно — пустой, единственный узел, копия, самоприсваивание и `std::string`.

### Вопросы для защиты

Почему одного обновления `next` недостаточно? Зачем `tail`? В чём различие между «вставить при известном адресе узла» и «вставить по индексу»? Почему после удаления головы нужно исправить `prev` у новой головы?

## Проект 3. `CollectionLab` — осознанная работа с STL

**Цель:** научиться применять `std::vector`, `std::list`, `std::deque` не только для хранения, но и для безопасных операций с итераторами, выбирать алгоритмы и обосновывать сложность.

Этот проект **намеренно использует STL** — это центральная тема второй половины четвёртой лекции. Не переносить запрет STL из первой лабораторной работы на эту независимую учебную задачу.

В `collection_operations.hpp` должны быть объявлены и определены следующие функции (все в `namespace collection_lab`):

```cpp
#include <cstddef>
#include <deque>
#include <list>
#include <vector>

namespace collection_lab {

void insert_marker_before_each_even(std::vector<int>& values, int marker);
void remove_negative(std::list<int>& values);
void rotate_left(std::deque<int>& values, std::size_t steps);
std::list<int> merge_sorted(std::list<int> first, std::list<int> second);

} // namespace collection_lab
```

### Обязательные контракты

**Операция 1 — `vector`:** вставить `marker` непосредственно перед **каждым исходным чётным элементом**, не обрабатывать добавленные маркеры как новые исходные элементы. Например, `{1,2,4,5}` и `marker=8` → `{1,8,2,8,4,5}`. Проверь отрицательные чётные числа и ноль. Нельзя хранить недействительные итераторы при вставке и реаллокации.

**Операция 2 — `list`:** удалить все строго отрицательные элементы; нули и положительные оставить в исходном порядке. В этой конкретной задаче использовать итераторный обход с корректным применением `erase`, чтобы закрепить правила инвалидирования; не заменять реализацию одним вызовом `remove_if`.

**Операция 3 — `deque`:** циклически сдвинуть элементы влево на `steps` позиций. Например, `{10,20,30,40}` и `steps=6` → `{30,40,10,20}`. Пустой дек не должен приводить к делению на ноль. Использовать операции на концах, не создавать вручную отдельную структуру данных.

**Операция 4 — `list`:** слить **два уже отсортированных по возрастанию списка** в новый отсортированный список, сохранив все дубликаты. Аргументы передаются по значению, поэтому исходные списки вызывающего кода не изменяются. Разрешено использовать `list::merge`. Не нужно дополнительно сортировать входные списки: это предусловие.

### Этапы

1. Спроектировать поведение и выбрать методы контейнеров.
2. Написать четыре функции самостоятельно.
3. Проверить пустые контейнеры, дубликаты, отрицательные значения, `steps > size()`.
4. Объяснить корректность итераторов.
5. Для каждой операции дать **оценку временной сложности и её обоснование**; если существуют разные корректные алгоритмы, оценка должна соответствовать собственному решению.

### Аналитическая часть проекта

Обязательные вопросы без готовых ответов на экране:

1. Почему вставка нескольких элементов в середину `vector` может потребовать квадратичного времени в наивной реализации?
2. Почему `std::list` не имеет `operator[]`?
3. Когда `std::list::splice` предпочтительнее последовательного копирования значений?
4. В чём разница `reserve` и `resize`?
5. Что значит «амортизированное `O(1)`» для `vector::push_back`?
6. Что произойдёт с сохранённым итератором на удалённый элемент списка?
7. Почему для `deque` нельзя предполагать сплошное расположение всех элементов?
