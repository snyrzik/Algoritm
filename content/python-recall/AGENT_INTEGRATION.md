# Техническое ТЗ для веб-агента: интеграция Python Recall

Контекст: у пользователя уже есть личный сайт с дисциплиной «Алгоритмы и структуры данных». **Не заменяй и не ломай существующий раздел.** Добавь самостоятельную дисциплину «Прикладное программирование · Python Recall» в ту же систему навигации и прогресса. Используй уже имеющийся технологический стек, архитектуру и оформление; не переписывай сайт целиком.

## Импорт и структура

1. Открой `import/public_catalog.json`. `weeks` содержит 8 недель, `tasks` — 40 дней с уникальным `id` `py-01` ... `py-40`. Поля: `week`, `day` (день недели, 1–5), `title`, `description`, `rules`, `signature`, `example`, `edges`, `hint`, `bonus`, `source_urls`, `dependencies`, `starter_code`, `explanation` и т.д.
2. Показывай недельный план с днями 1–5. Не требуй календарной даты и не блокируй переход к нужному заданию; программа должна работать в своём темпе.
3. На странице задачи показывай условие, критерии, пример, примерное время 15–25 мин, теги тем и происхождение из лекций/лабораторных. Подсказку скрывай до клика. Усложнение — отдельная необязательная секция.
4. Редактор Python заполняй `starter_code` или `starter_files`. При необходимости поддержи несколько файлов для дня 14.
5. Прогресс: not_started / in_progress / completed / revisit. Желательно хранить код попытки и список конструкций для повторения. Не дублируй данные существующей дисциплины.
6. Задания 21–23, 25–29, 31–34, 36–37 относятся к специфическим лабораторным темам. Считай их дополнительными до подтверждения пользователем, что тема уже пройдена. Должна быть возможность пропустить день/выбрать повторение.

## Решения и безопасность

`import/private_solutions.json` — **закрытые данные** для импорта на сервере, содержит код решений и пояснения. Не включай этот файл или папку `solutions/` в публичную статику и не отдавай их браузеру автоматически. Сделай кнопку «Показать эталон» только после попытки или явного подтверждения. Не запускай непроверенный Python пользователя прямо в процессе основного сервера. Если нужна кнопка Run/Check, используй изолированный раннер (контейнер/процесс с жёсткими лимитами CPU, памяти, времени, сети и файловой системы), либо предложи локальный запуск. GUI на PyQt5 в обычном браузерном раннере не проверяется автоматически — требуются ручные критерии.

## Тестирование и отображение

Эталонные решения лежат в `solutions/`; `tests/test_solutions.py` — Python-тесты самих решений, а не готовый сервис запуска пользовательского кода. Их можно использовать как основу собственного проверяющего механизма, но не отправляй закрытые тесты клиенту. Для файловых задач используй временные файлы; для классов — проверку последовательности вызовов методов. Для GUI — ручная проверка интерфейса.

Обязательно убедись, что JSON валиден, все 40 ID импортированы, все 8 недель и 5 дней отображаются, публичная выдача не содержит приватных решений, существующий предмет «Алгоритмы и структуры данных» не повреждён.

## Не обязательные, но полезные мелочи

- Ненавязчивый таймер 20 минут, который можно отключить.
- Кнопки «Подсказка», «Сравнить с решением», «Отметить для повторения».
- Выбор «Слишком легко / Нормально / Сложно» после решения; слабые темы должны периодически повторяться.
- Ссылки на соответствующие материалы курса (уже есть в `source_urls`).

## Критерии готовности

- [ ] Новый курс доступен рядом с алгоритмами, без изменений их прогресса.
- [ ] 8 недель, 40 задач, порядок и уникальные ID верны.
- [ ] Условия, примеры, границы, подсказки и усложнения отображаются корректно.
- [ ] Стартеры доступны в редакторе.
- [ ] Эталонные решения не попадают в публичные ассеты.
- [ ] Пользователь может сохранять решение и свой прогресс.
- [ ] Поздние лабораторные темы можно пропускать, если ещё не изучены.
