### Проект 1: `CMyString` — расширение своего класса

**Не создавать второй класс-замену и не выдавать новую готовую реализацию `CMyString`.** Пользователь продолжает свой класс из лекции № 1.

Ожидаемый публичный API, включая базовые методы:

```cpp
class CMyString {
public:
    CMyString();
    explicit CMyString(const char* text);
    CMyString(const CMyString& other);
    CMyString& operator=(const CMyString& other);
    ~CMyString();
    std::size_t size() const;
    const char* c_str() const;
    // Имеются операторы доступа и прочие методы лекции 1.

    void erase(std::size_t position, std::size_t count);
    void replace_range(std::size_t position,
                       std::size_t count,
                       const char* replacement);
};
```

Контракт новых операций:

- Для `erase` проверять интервал; недопустимый диапазон — `std::out_of_range`; изменения при ошибке запрещены.
- `erase` не выделяет новый буфер и не меняет указатель, возвращаемый `c_str()`. При допустимой операции сдвигается содержимое существующего буфера.
- `position == size()` допустима только при `count == 0`.
- `replace_range` принимает только ненулевой `replacement` (для `nullptr` — `std::invalid_argument`).
- При неверной позиции или числе удаляемых символов — `std::out_of_range`, объект остаётся неизменным.
- Смена длины, пустая вставка и замена всей строки должны работать.
- Если `replacement` указывает в собственный буфер (`s.c_str() + offset`), операция обязана сохранять корректность.
- При ошибке выделения памяти и других ошибках подготовки результата обеспечивать **сильную гарантию исключений**.
- Проверять размер до потенциально переполняющих выражений с `std::size_t`, при недопустимой итоговой длине — `std::length_error`.
- Соблюдать инварианты `m_data`, `m_size` и завершающего `\0`.
- Внутреннее хранение — собственный буфер с корректным управлением памятью; не заменять его единственным `std::string`.

**Этапы для интерфейса:** проверка диапазонов → удаление в существующем буфере → подготовка новой строки → обработка самоалиасинга → проверка исключений и памяти.

Предоставь файл `MAIN_CMYSTRING_EDITING.cpp` на вкладке «Проверить на своём компьютере» с возможностью просмотра, копирования и скачивания. Это единственный проверочный main проекта; не заменяй его фреймворком.

### Проект 2: `DynamicVector` — изменение длины

Продолжаем класс из лекции № 1 с `double`-элементами и собственным динамическим буфером. Не создавать параллельный `Vector2`/`NewVector`/`SafeVector`.

Обязательный новый API:

```cpp
void resize(std::size_t new_size, double fill = 0.0);
void insert(std::size_t index, double value);
void erase(std::size_t index);
```

Точный контракт:

- `resize` сохраняет префикс существующих элементов; при увеличении новые элементы равны `fill`; при уменьшении остаётся корректный префикс; при неизменной длине содержимое не изменяется.
- `insert` вставляет элемент перед индексом. Индекс `size()` допустим — добавление в конец; индекс больше `size()` вызывает `std::out_of_range`.
- `erase` удаляет элемент с указанным индексом. Индекс `size()` и больше — `std::out_of_range`. Удаление существующего элемента выполняется **без перевыделения буфера**, пока размер был положительным; вместимость может оставаться прежней.
- `resize` и `insert` при необходимости создания нового массива обязаны сохранять старое состояние при неудачной аллокации.
- Копии объектов независимы; самоприсваивание не ломает работу.
- Для пустого вектора допустимы `resize`, `insert(0, value)`; `erase(0)` в пустом — ошибка.
- Старые операции из первой лекции, в том числе `operator[]`, `size()` и конструктор `(std::size_t, double)`, остаются работоспособными.

**Этапы:** продумать инварианты → реализовать изменение размера → вставка → удаление без новой аллокации → тестирование исключений и пустого случая.

Предоставь `MAIN_DYNAMICVECTOR_EDITING.cpp` без изменений.

## Компиляция только на компьютере ученика

**Не создавай серверного, браузерного или облачного C++-компилятора.** Не запускай код ученика автоматически. Не создавай кнопку `Run` с фиктивным результатом. Если на существующем сайте есть подобная функция, не имитируй её использование в новых лекциях; показывай понятные инструкции для локальной сборки.

Для GCC/Clang в терминале:

```bash
g++ -std=c++17 -Wall -Wextra -Wconversion -Wpedantic \
    MAIN_CMYSTRING_EDITING.cpp CMyString.cpp -o string_edit_test
./string_edit_test

g++ -std=c++17 -Wall -Wextra -Wconversion -Wpedantic \
    MAIN_DYNAMICVECTOR_EDITING.cpp DynamicVector.cpp -o vector_edit_test
./vector_edit_test
```

Если реализации header-only, удали соответствующий `.cpp` из команды. В Windows PowerShell запуск исполняемого файла обычно выглядит как `.\string_edit_test.exe`.

Для задач с памятью предложи дополнительный локальный запуск с поддерживаемыми GCC/Clang санитайзерами:

```bash
g++ -std=c++17 -g -O1 -Wall -Wextra -Wconversion -Wpedantic \
    -fsanitize=address,undefined -fno-omit-frame-pointer \
    MAIN_CMYSTRING_EDITING.cpp CMyString.cpp -o string_asan
./string_asan
```

Уточни, что санитайзеры доступны не везде и не гарантируют выявления **всех** ошибок. Тестовые `main` используют `assert`; **не компилировать с `-DNDEBUG`**.

После локального запуска ученик вручную фиксирует результат в сайте: «Проверил локально», «Есть ошибки», «Нужно повторить». Такой статус нельзя выдавать за автоматически подтверждённое прохождение тестов.
