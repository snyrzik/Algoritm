# C++ Mastery — готовые лекции № 2 и № 3

Этот комплект продолжает уже подготовленную **лекцию № 1**, но предназначен для **уже работающего сайта**, а не для создания нового приложения.

## Как использовать

1. Распакуй архив.
2. Открой существующий репозиторий сайта в Codex.
3. Передай папку `lecture-02/` и попроси выполнить `lecture-02/CODEX_INSTRUCTIONS.md`.
4. Затем передай папку `lecture-03/` и попроси выполнить `lecture-03/CODEX_INSTRUCTIONS.md`.
5. Никаких дополнительных исходных PDF ему не нужно: теории написаны полностью.

Можно применить оба модуля одной задачей Codex, но безопаснее выполнять последовательно, проверяя навигацию и сохранность старого прогресса после каждого.

## Главное о статусе лекций

- **Лекция № 2:** оригинальный файл преподавателя недоступен. Это явно обозначенный **переходный модуль**, восстановленный для объяснения памяти, владения ресурсом и исключений. Он продолжает классы первой лекции.
- **Лекция № 3:** основана на 25 слайдах оригинальной презентации Е. В. Мясникова «Шаблоны. Приведение типов и RTTI». Материал сохранён по исходной последовательности тем, с дополнительными пояснениями для C++17.

## Состав комплекта

### `lecture-02/`

- `LECTURE_02_THEORY.md`: четыре полноценные главы теории, четыре закрепления.
- `CODEX_INSTRUCTIONS.md`: точные правила интеграции, API проектов, требования безопасности и локальной компиляции.
- `MAIN_CMYSTRING_EDITING.cpp`: локальные проверки `erase` и `replace_range`.
- `MAIN_DYNAMICVECTOR_EDITING.cpp`: локальные проверки `resize`, `insert`, `erase`.

**Два проекта:** расширение уже созданного `CMyString` и расширение существующего `DynamicVector`. Не нужно писать заново два ресурсных класса ради небольших новых операций.

### `lecture-03/`

- `LECTURE_03_THEORY.md`: четыре большие главы, четыре закрепления, все основные темы 25 слайдов.
- `CODEX_INSTRUCTIONS.md`: API и критерии трёх самостоятельных проектов.
- `MAIN_GENERIC_FUNCTIONS.cpp`: универсальные функции, перегрузка и специализация.
- `MAIN_FIXED_STACK.cpp`: шаблонный стек фиксированной вместимости.
- `MAIN_LINKED_STACK.cpp`: абстрактный интерфейс, связный стек, глубокое копирование.
- `MAIN_POSTFIX.cpp`: вычисление выражения в постфиксной записи на своём `LinkedStack<double>`.
- `MAIN_RTTI.cpp`: короткая проверка `dynamic_cast`, `typeid` и полиморфизма.

**Три проекта:** функции-шаблоны; фиксированный стек; копируемый динамический стек, который затем используется для решения прикладной задачи. RTTI — отдельное небольшое закрепление.

## Где компилируется C++

**Только на компьютере ученика** — в VS Code, CLion, Visual Studio или терминале с GCC/Clang/MSVC. Сайт служит учебником, показывает код проверочного `main`, позволяет скачать его и вручную сохранить прогресс. Никакого компилятора на сайте или сервере нет.

К каждому проекту прилагается обычный `main` с понятными `assert`. Пример использования:

```bash
g++ -std=c++17 -Wall -Wextra -Wconversion -Wpedantic \
    MAIN_GENERIC_FUNCTIONS.cpp -o generic_test
./generic_test
```

Размести соответствующий проверочный файл рядом со своим заголовком и исходниками. Если реализация в отдельных `.cpp`, добавь их к команде компиляции. Для проверки памяти при поддержке инструментария используй AddressSanitizer и UndefinedBehaviorSanitizer. **Не включай `-DNDEBUG`**, чтобы не отключить `assert`.

## Что проверено при подготовке комплекта

- Все проверочные `main` скомпилированы с GCC C++17 и строгими флагами **в тестовом окружении с временными эталонными заглушками интерфейсов**.
- Все проверки успешно выполнены в этом тестовом окружении.
- Полные программы, приведённые внутри теоретических глав, дополнительно проверены на корректность синтаксиса с GCC C++17.

Это проверка совместимости **условий и предоставленных main**. Она **не утверждает**, что пользовательские классы уже реализованы или протестированы. Реальную реализацию должен написать ученик.

## Политика обучения

- Теория написана заранее; Codex **не переписывает её**.
- Готовые решения проектов **не включены**.
- В конце главы — одно содержательное закрепление, а не десяток микроупражнений.
- Освоение подтверждается самостоятельной реализацией, аргументацией и локальными проверками.
- Успешный единичный `main` не является доказательством отсутствия всех ошибок. Особенно для ресурсных классов полезны дополнительные сценарии, санитайзеры и ручное ревью.

## Рекомендуемый порядок

1. Первая лекция: операторы, `CMyString`, `DynamicVector` — уже пройдена/готовится.
2. Вторая лекция: безопасность памяти и расширение этих классов.
3. Третья лекция: шаблоны функций и классов, наследование, стек, специализация и RTTI.
4. После третьей лекции: самостоятельно обобщить ресурсный класс до шаблона и приступить к лабораторной № 1.
