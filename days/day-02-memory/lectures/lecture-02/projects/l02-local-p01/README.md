### Проект 1: `CMyString` — расширение своего класса

**Не создавать второй класс-замену и не выдавать новую готовую реализацию `CMyString`.** Пользователь продолжает свой класс из лекции № 1.

Ожидаемый публичный API, включая базовые методы:

```cpp
class CMyString {
public:
    CMyString();
    explicit CMyString(const char* text);
    CMyString(const CMyString& other);
    CMyString& operator=(const CMyString& other);
    ~CMyString();
    std::size_t size() const;
    const char* c_str() const;
    // Имеются операторы доступа и прочие методы лекции 1.

    void erase(std::size_t position, std::size_t count);
    void replace_range(std::size_t position,
                       std::size_t count,
                       const char* replacement);
};
```

Контракт новых операций:

- Для `erase` проверять интервал; недопустимый диапазон — `std::out_of_range`; изменения при ошибке запрещены.
- `erase` не выделяет новый буфер и не меняет указатель, возвращаемый `c_str()`. При допустимой операции сдвигается содержимое существующего буфера.
- `position == size()` допустима только при `count == 0`.
- `replace_range` принимает только ненулевой `replacement` (для `nullptr` — `std::invalid_argument`).
- При неверной позиции или числе удаляемых символов — `std::out_of_range`, объект остаётся неизменным.
- Смена длины, пустая вставка и замена всей строки должны работать.
- Если `replacement` указывает в собственный буфер (`s.c_str() + offset`), операция обязана сохранять корректность.
- При ошибке выделения памяти и других ошибках подготовки результата обеспечивать **сильную гарантию исключений**.
- Проверять размер до потенциально переполняющих выражений с `std::size_t`, при недопустимой итоговой длине — `std::length_error`.
- Соблюдать инварианты `m_data`, `m_size` и завершающего `\0`.
- Внутреннее хранение — собственный буфер с корректным управлением памятью; не заменять его единственным `std::string`.

**Этапы для интерфейса:** проверка диапазонов → удаление в существующем буфере → подготовка новой строки → обработка самоалиасинга → проверка исключений и памяти.

Предоставь файл `MAIN_CMYSTRING_EDITING.cpp` на вкладке «Проверить на своём компьютере» с возможностью просмотра, копирования и скачивания. Это единственный проверочный main проекта; не заменяй его фреймворком.

### Совместимость с вашей первой лекцией

Проверочный файл пакета включает `.h`, а первая лекция использует `.hpp`. Файл `.h` в черновике — только переходный include вашего `.hpp`; он не содержит реализации класса. Если ваш код уже сохранён на сайте, его текущая версия один раз копируется в новый черновик. Исходные файлы и результаты первой лекции не изменяются. Можно продолжить тот же класс напрямую в своей IDE.
