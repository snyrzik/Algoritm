### Проект 2: `DynamicVector` — изменение длины

Продолжаем класс из лекции № 1 с `double`-элементами и собственным динамическим буфером. Не создавать параллельный `Vector2`/`NewVector`/`SafeVector`.

Обязательный новый API:

```cpp
void resize(std::size_t new_size, double fill = 0.0);
void insert(std::size_t index, double value);
void erase(std::size_t index);
```

Точный контракт:

- `resize` сохраняет префикс существующих элементов; при увеличении новые элементы равны `fill`; при уменьшении остаётся корректный префикс; при неизменной длине содержимое не изменяется.
- `insert` вставляет элемент перед индексом. Индекс `size()` допустим — добавление в конец; индекс больше `size()` вызывает `std::out_of_range`.
- `erase` удаляет элемент с указанным индексом. Индекс `size()` и больше — `std::out_of_range`. Удаление существующего элемента выполняется **без перевыделения буфера**, пока размер был положительным; вместимость может оставаться прежней.
- `resize` и `insert` при необходимости создания нового массива обязаны сохранять старое состояние при неудачной аллокации.
- Копии объектов независимы; самоприсваивание не ломает работу.
- Для пустого вектора допустимы `resize`, `insert(0, value)`; `erase(0)` в пустом — ошибка.
- Старые операции из первой лекции, в том числе `operator[]`, `size()` и конструктор `(std::size_t, double)`, остаются работоспособными.

**Этапы:** продумать инварианты → реализовать изменение размера → вставка → удаление без новой аллокации → тестирование исключений и пустого случая.

Предоставь `MAIN_DYNAMICVECTOR_EDITING.cpp` без изменений.

### Совместимость с вашей первой лекцией

Проверочный файл пакета включает `.h`, а первая лекция использует `.hpp`. Файл `.h` в черновике — только переходный include вашего `.hpp`; он не содержит реализации класса. Если ваш код уже сохранён на сайте, его текущая версия один раз копируется в новый черновик. Исходные файлы и результаты первой лекции не изменяются. Можно продолжить тот же класс напрямую в своей IDE.
