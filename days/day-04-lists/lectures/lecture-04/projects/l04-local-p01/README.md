## Проект 1. `ForwardChain<T>` — полноценный односвязный список

**Цель:** применить указатели, структуру узла, деструктор, глубокое копирование, `const`, исключения, поиск/удаление и разворот цепочки.

Не нужно создавать десять маленьких классов. Реализуется один связный контейнер.

### Обязательный публичный интерфейс

Контракт вызовов должен соответствовать готовому проверочному файлу `MAIN_FORWARD_CHAIN.cpp`:

```cpp
#include <cstddef>

template <typename T>
class ForwardChain {
public:
    ForwardChain();
    ForwardChain(const ForwardChain& other);
    ForwardChain& operator=(const ForwardChain& other);
    ~ForwardChain();

    bool empty() const;
    std::size_t size() const;
    const T& front() const;

    void push_front(const T& value);
    T pop_front();
    bool contains(const T& value) const;
    bool erase_first(const T& value);
    void reverse();
    void clear();
};
```

Это **описание контракта API, а не готовое решение**. На странице задания можно показывать требования словами, а сигнатуры спрятать в отдельную вкладку «Сверить интерфейс после самостоятельной попытки»; однако для совместимости с `main` ученик должен иметь возможность открыть точный контракт.

### Семантика

- Изначально список пуст.
- `push_front` ставит новый элемент первым.
- `front` возвращает ссылку на первый элемент; на пустом списке бросает `std::out_of_range`.
- `pop_front` удаляет первый элемент и возвращает его значение; на пустом списке бросает `std::out_of_range`.
- `contains` ищет первое совпадение, используя `operator==` типа `T`.
- `erase_first` удаляет **только первое** совпадение; возвращает `false`, если значение отсутствует.
- `reverse` изменяет порядок узлов **на месте** и не выделяет массив с копиями элементов. Время `O(N)`, дополнительная память `O(1)`.
- `clear` освобождает все узлы; повторный вызов допустим.
- Копирование означает независимое **глубокое копирование всей цепочки** с сохранением порядка элементов.
- Самоприсваивание безопасно.
- Инвариант `size()` всегда совпадает с количеством достижимых узлов.

### Этапы проекта

1. Пустой список, `Node`, создание/удаление узлов.
2. Вставка в голову, чтение, удаление из головы.
3. Поиск значения и удаление первого совпадения.
4. Разворот списка без дополнительных узлов и массива.
5. Правило трёх, независимость копий, самоприсваивание.
6. Локальные проверки, дополнительные собственные тесты, объяснение сложности.

### Дополнительные строгие проверки

- Пустой список.
- Единственный узел.
- Дубликаты в начале и середине.
- Отсутствующее значение.
- Разворот пустого и одноэлементного списка.
- Копирование пустого списка.
- Копирование списка с `std::string`.
- Самоприсваивание.
- Уничтожение без утечек.
- Поведение, когда копирование элемента `T` бросает исключение: сохранять корректность ресурса и не оставлять недоступные узлы (можно рассмотреть как расширенный уровень проверки).

### Вопросы для защиты

Почему `push_front` занимает `O(1)`? Почему `erase_first` обычно требует `O(N)`? Почему нельзя просто копировать `head`? Почему `reverse` можно сделать без выделения новых узлов? Чем отличается ссылка на указатель от указателя по значению?
