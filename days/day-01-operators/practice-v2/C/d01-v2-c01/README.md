# C1 · StereoLab Console

**Это кульминация всего Дня 1, а не повторение A1–A3.** Написать самостоятельную программу (или библиотечную функцию плюс небольшой `main`) для обработки короткой последовательности стереоотсчётов. Разрешены лишь собственные классы A1–A3 и стандартные потоки/математические заголовки; готовые контейнеры не использовать.

### Входной контракт

Один сценарий обработки содержит:

```
N
(L1,R1)
...
(LN,RN)
[[a,b],[c,d]]
[[e,f],[g,h]]
```

`N` — целое число от 0 до 4. Первое преобразование применяется раньше второго. Данные могут иметь пробелы и переносы строк.

### Выходной контракт

При успешном чтении программа выводит:

```
count=N
input_power=...
output_power=...
first=(...,...)
last=(...,...)
```

Если `N=0`, вывести `first=none` и `last=none`.

Выводимые мощности проверять численно (погрешность `1e-9`) с парсингом значений, а не по конкретному количеству знаков после десятичной точки.

### Обработка ошибок

- `N < 0` или `N > 4`: выбросить `std::out_of_range` в функции обработки сценария. В `main` обработать исключение и вывести понятную диагностику в `std::cerr`; код завершения не равен нулю. Не преобразовывать отрицательное `N` в `std::size_t` до проверки.
- Ошибка формата в любой строке отсчёта или микшера: `failbit`; программа не должна публиковать частичный «успешный» отчёт. Ошибочный сценарий возвращает ненулевой код и диагностическое сообщение в `std::cerr`.
- До успешной проверки всего сценария не выводить итоговые показатели в `std::cout`. Можно собирать временные значения и публиковать отчёт только после успешного чтения всех данных.
- Конечные числовые значения; `NaN` и бесконечности не входят в область тестов.

### Проверки независимости и копирования

- Преобразование возвращает новый блок; начальный блок не изменяется.
- Скопированный блок можно изменять независимо.
- Левое и правое умножение масштабирования `StereoSample` работает согласованно.
- `operator[]` позволяет изменить нужный канал, не соседний.

### Нетривиальные испытания

- Пустая запись и два микшера.
- Четыре отсчёта; два некоммутирующих микшера.
- Комбинация с отрицательными коэффициентами.
- Первый микшер — единичный.
- Второй микшер — перестановка каналов.
- Ошибочная закрывающая скобка в последнем микшере.
- Некорректное `N`.
- Проверка, что `output_power` считается по **результату двух преобразований**, а не только первого.
- Проверка, что `first` и `last` относятся к преобразованной последовательности.

### Что оцениваем в C1

1. Выбранные учеником структуры и корректная композиция объектов.
2. Семантика перегруженных операторов и выбранные сигнатуры.
3. Правильная `const`-корректность.
4. Понимание копирования по значению без ручной динамической памяти.
5. Сохранение состояния объектов при ошибках ввода.
6. Отсутствие дублирования вычислительного кода.
7. Читаемый `main`, в котором оркестрация отделена от вычислений.
8. Проверка данных и корректное завершение.
9. Чистая компиляция с предупреждениями.
10. Прохождение сложных скрытых сценариев.

Проверяется ваша программа main.cpp. Заголовки StereoSample.hpp / ChannelMix.hpp / AudioBlock.hpp / StereoIO.hpp / StereoPipeline.hpp подключают ваши A1–A3 и B1–B2. До готовности зависимостей сообщается, какого исходника не хватает; готовые решения не подставляются. Для раздельной проверки исключения обработки сценария объявите в solution.hpp функцию int run_stereolab(std::istream&,std::ostream&); она возвращает 0 при успехе, бросает out_of_range для N вне 0..4. main должен её вызвать, обработать ошибки и написать диагностику в cerr. Достаточную точность чисел обеспечьте форматированием потока; фиксированное число знаков не требуется.
