# A2 · ChannelMix

### A2. `ChannelMix` — преобразование и композиция функций

**Сюжет:** матрица смешивания двух каналов. Сигнал `(L,R)` переходит в `(aL + bR, cL + dR)`.

**Контракт:**

- Хранит четыре коэффициента `double` в логическом порядке `a,b,c,d` (2×2).
- Конструктор по умолчанию представляет единичное преобразование `[[1,0],[0,1]]`.
- Конструктор из четырёх коэффициентов задаёт явное преобразование.
- `mix(sample)` реализуется **через `operator()`** и возвращает новый `StereoSample`; исходный sample не меняется.
- `mix_a * mix_b` реализует композицию преобразований: **сначала `mix_b`, затем `mix_a`**. Произведение коэффициентов — обычное произведение матриц 2×2.
- Сравнение `==` и `!=` по четырём коэффициентам с допуском `1e-9`.
- Потоковый вывод `[[a,b],[c,d]]`.
- Корректная работа с `const ChannelMix` и `const StereoSample`.
- Использовать методы `StereoSample`, а не нарушать его инкапсуляцию. Не делать `ChannelMix` другом `StereoSample` без необходимости.

**Контрольные случаи:**

- Единичный `ChannelMix` оставляет `(3,-2)` неизменным.
- `swap = [[0,1],[1,0]]` меняет каналы: `(3,-2) → (-2,3)`.
- `gain = [[2,0],[0,3]]` переводит `(1,2) → (2,6)`.
- `swap * gain` означает: сначала `(1,2)→(2,6)`, потом `(6,2)`.
- `gain * swap` означает: сначала `(1,2)→(2,1)`, потом `(4,3)`.
- Два разных порядка композиции должны дать разные результаты на подобранном примере; тест должен обнаруживать перепутанный порядок.


Для автономной проверки включите StereoSample.hpp: тип отсчёта предоставляется тестовым окружением с описанными в A1 конструкторами и методами. Эта проверка оценивает только ваш ChannelMix. В B/C будут подключены именно ваши исходники A1.
