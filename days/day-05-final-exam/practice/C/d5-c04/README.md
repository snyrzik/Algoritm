# d5-c04 · C+ · Move-семантика (расширение)

Создайте с нуля template<class T> class TSequence. Хранение — собственный динамический массив new T[], без std::vector/deque/list/array/string и других контейнеров для хранения, без RTTI-выбора поведения. Тип T: конструктор по умолчанию, копирование и присваивание; == нужен только при сравнении, << только при выводе. Нельзя требовать <. Обязательны: пустой конструктор; explicit-конструктор TSequence(std::size_t count) с value-initialized элементами; правило трёх; size() const -> size_t, empty() const -> bool; две версии [](size_t) -> T& / const T&; void push_back(const T&); void insert(size_t position,const T&); void erase(size_t position); ==, !=; вывод [a,b,c] (пустой: []). insert принимает position<=size, []/erase требуют position<size, иначе out_of_range. Сначала проверяйте границы, затем изменяйте объект. Поддержите самостоятельное владение, независимость копий, цепочку присваиваний, самоприсваивание, рост и алиасинг push_back(s[0])/insert(0,s[1]). Все изменяющие операции и копирование обеспечивают сильную гарантию при исключении: ресурсы не теряются, старое состояние сохраняется. Проверяйте переполнение количества и байтов до выделения, бросайте length_error. Не перехватывайте и не скрывайте bad_alloc/ошибки T. Требования к T позволяют использовать new T[capacity]. Проверки используют int, double, std::string как значение элемента (допустимо), и Tracked — пользовательский тип с копированием, ==, <<, без <, иногда бросающий из копирования. Реализуйте заголовок самостоятельно; стартового решения нет.

Дополнительная сложность за рамками основной программы: добавьте noexcept move-конструктор и move-присваивание. Перемещённый объект должен быть пустым, безопасным для повторного push_back и уничтожения; самоперемещение допустимо. Не входит в обязательный процент.
