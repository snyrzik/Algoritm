# C++ Mastery

Локальная платформа пятидневного повторения C++17. **288 активных заданий и четыре отдельных закрепления теории. День 1 — StereoLab: 48 заданий, 130 баллов; 52 прежних задания сохранены в архиве.** Все результаты получаются реальной компиляцией и запуском. Начальные решения не заполнены.

## Запуск

Требуются Node.js 22.12+ (подходит 24), Python 3.10+ и компилятор: GCC, Clang либо установленный компонент Desktop development with C++ в Visual Studio / Build Tools на Windows.

```powershell
cd C:\HTLLub\cpp-mastery
npm install
npm start
```

Откройте **http://127.0.0.1:8765/#/day/1** и нажмите **«Начать диагностику»**. Ответы заранее не показываются. При первом старте создаются недостающие файлы ученика и собирается интерфейс. Существующие решения никогда не заменяются генератором курса.

Остановка сервера — Ctrl+C в терминале запуска. Режим разработки с обновлением интерфейса: `npm run dev`, адрес http://127.0.0.1:5173. После изменения исходников для обычного запуска выполните `npm run build`.

Работа с платформой не требует внешних сервисов после установки зависимостей. Внешние шрифты, CDN и удалённые компиляторы не используются.

## Курс

| День | Основная тема | Q | S | P | D | C |
|---|---|---:|---:|---:|---:|---:|
| 1 | StereoLab: StereoSample, ChannelMix, AudioBlock, потоки | 16 | 14 | 6 | 6 | 6 (A3/B2/C1) |
| 2 | C-строки, CMyString, память, правило трёх, исключения | 15 | 18 | 5 | 8 | 8 |
| 3 | Шаблоны функций, перегрузка, специализация | 15 | 20 | 5 | 8 | 9 |

| 5 | Смешанный экзамен и TSequence<T> | 30 | 20 | 5 | 10 | 3 + 1 расширение |

Q — теория, S — воспроизведение синтаксиса, P — предсказание, D — отладка, C — программирование с уровнями A/B/C. Все основные уровни обязательны. Переход между днями свободный, долги сохраняются.

Рабочий ритм: 20–35 минут диагностики; 40–60 минут синтаксиса; 20–30 минут предсказаний; 40–60 минут отладки; 120–180 минут практики и разбора. Ориентир — 4–6 часов основной работы. Полное закрытие сложных задач может потребовать дополнительного времени. В StereoLab A2/A3 проверяются автономно, а B/C подключают **ваши** сохранённые компоненты A1–A3 и B1–B2. О незавершённой зависимости платформа сообщает явно. Остальные дни сохраняют прежнюю организацию упражнений.


Подробности новой практики, расчёта баллов, зависимостей и архива: [StereoLab v2](docs/day01-stereolab-v2.md).

## Редактор и реальные файлы

- Выберите день, блок и задание. У каждого C++-задания есть полный контракт, граничные случаи и перечень проверок.
- `solution.hpp` — определения шаблонов, объявления или полная реализация упражнения. Добавляйте требуемые заголовки самостоятельно.
- `solution.cpp` — дополнительный файл для нешаблонных определений. При необходимости включите `solution.hpp`; не дублируйте определения в двух единицах трансляции.
- `notes.md` — объяснение ошибок и проектных решений. В отладочных задачах письменный разбор обязателен; его содержание проверяется самостоятельно, а не фиктивным автоматическим оценщиком.
- В синтаксических упражнениях иногда дан окружающий контекст. Он показан в условии и добавляется системой; вставляйте в редактор только требуемый фрагмент.
- Редактор поддерживает C++, номера строк, Tab, автоотступ, undo/redo. Сохраняет на диск через 0,8 секунды, при переходе и перед проверкой.
- Можно редактировать те же файлы в VS Code. Вернитесь в окно платформы либо нажмите **«С диска»**. При конфликте редактор не перезаписывает внешнюю правку: сохраняет браузерный черновик, а при загрузке диска предлагает его скачанный JSON для объединения.

Решения StereoLab: `student/day-01/d01-v2-s01/solution.hpp` и аналогичные папки. Они отделены от платформы и игнорируются Git. Для резервного копирования сохраните **student/** и **progress/**. Генератор не удаляет и не обнуляет прогресс.

**«Скомпилировать»** проверяет реальный тестовый контракт, типы и сборку, но не начисляет выполнение. **«Запустить тесты»** компилирует и запускает каждый сценарий отдельно; показывает PASS/FAIL, вывод, исключения и тайм-ауты. Пустые начальные файлы ожидаемо дают ошибку компиляции — это не сбой платформы.

## Проверка из терминала

```powershell
npm run doctor
npm run check -- --task d01-v2-s01
npm run check -- --task d2-c07 --compile
npm run check -- --day 3
npm run check -- --task d5-c01 --no-record
```

Обычная CLI-проверка сохраняется в общей истории. `--no-record` запускает проверки без записи попытки. Непройденные упражнения дают ненулевой exit code; одно упражнение не останавливает проверку остальных заданий дня.

GCC/Clang: `-std=c++17 -Wall -Wextra -Wconversion -Wpedantic -Werror`. Windows MSVC: `/std:c++17 /W4 /WX /permissive- /EHsc /utf-8`; `/wd4996` разрешает изучаемые стандартные C-функции без навязывания непереносимых MSVC-замен. Компилятор автоматически обнаруживается; для GCC/Clang можно задать переменную `CXX` с путём к исполняемому файлу (без дополнительных аргументов).

MSVC найден и проверен на этом компьютере вместе с AddressSanitizer. **UBSan и LeakSanitizer в этой MSVC-конфигурации недоступны** — интерфейс явно показывает это. Для всех C++-сценариев дополнительно проверяются баланс обычных `new/delete`, соответствие массивного освобождения, а для владеющих классов — отказ выделения и время жизни тестового типа. Этот счётчик не является универсальной заменой LeakSanitizer для `malloc`, переопределённых аллокаторов и расширенного выравнивания. На Linux GCC/Clang при доступности запускаются ASan/UBSan/LSan. Доступность ASan проверяется как успешным запуском, так и обнаружением специально внедрённого дефекта.

При отсутствии ASan память отмечается как неподтверждённая; небезопасные стартовые фрагменты без защиты не выполняются. Смысл объяснений, читаемость кода, наличие всех проектных решений и авторство не выдаются за автоматические проверки. Простые статические ограничения проверяют запрет контейнеров/RTTI и вынесенные методы, но не заменяют полный анализ AST.

## Прогресс и строгая оценка

`progress/mastery.sqlite3` хранит все попытки: дату, исходный код, режим, результаты каждого теста, первую/последнюю проверку и число использованных подсказок. История доступна в задании; снимки можно скачать. В разделе результатов экспортируется JSON истории. Данные сохраняются после перезапуска приложения.

Процент завершения — доля **обязательных заданий**, у которых последняя полноценная проверка успешна. Процент внутри попытки — доля прошедших C++-сценариев. Компиляция без тестов не означает PASS. Ошибки памяти, недоступная проверка памяти, статические нарушения и отсутствие разбора отладки не скрываются за процентом.

Устойчивое освоение темы требует ≥95%, не менее трёх самостоятельных заданий, успешных попыток минимум в две разные календарные даты и отсутствия текущих ошибок. Просмотр подсказок учитывается отдельно. Новые задания по слабым темам доступны в разделе **«Ошибки и повторение»**. Автоматический PASS не является доказательством отсутствия любых возможных ошибок вне проверенных сценариев.

## Экзамен

День 5: 30 новых смешанных вопросов (10/10/10 по синтаксису, поведению, проектированию), 20 заданий воспроизведения, 5 предсказаний, 10 независимых review-фрагментов, основной TSequence, универсальный клиент и интеграция с CMyString. Некоторые review-фрагменты намеренно корректны. Move-семантика отдельно обозначена как необязательное расширение.

Выберите тренировку без таймера или экзамен на 6 часов. В экзамене синтаксические задания перемешиваются, на каждое отводится 4 минуты с первого открытия. Перезагрузка страницы не сбрасывает серверный таймер. Подсказки отключены, объяснения теоретических ответов открываются после окончания сессии. Время включает компиляцию/проверку. Завершённую сессию можно сменить новой тренировкой; история остаётся.

## Архитектура и проверки платформы

```text
app/src/           React + TypeScript + CodeMirror, собственный CSS
backend/           Python stdlib: HTTP, компилятор, оценка, SQLite
days/day-*/        отдельные условия, вопросы и C++-тесты пяти дней
student/day-*/     ваши файлы (создаются без готовых решений)
tools/content/     авторские исходники всего курса
tools/             генерация, CLI, тестовый раннер, контроль аллокаций
tests/             изолированные проверки инфраструктуры и контрактов
progress/          база истории (не публикуется и не коммитится)
docs/              карта покрытия, ограничения, исходное ТЗ
```

```powershell
npm run build
npm test
npm run test:contracts
npm run test:browser
```

Браузерная проверка использует установленный Chrome/Chromium: задайте `PUPPETEER_EXECUTABLE_PATH`, либо используется уже имеющийся кэш Puppeteer. Браузер автоматически не скачивается. Скриншоты — `test-results/`. Все тесты используют временный профиль и не записывают учебные решения/оценки в ваш профиль.

Дополнительный CMake-вход:

```powershell
cmake -S . -B .build/cmake
ctest --test-dir .build/cmake -C Debug --output-on-failure
cmake --build .build/cmake --config Debug --target day-1
```

`ctest` проверяет инфраструктуру; `day-1`…`day-5` проверяют реальные текущие решения и ожидаемо падают на невыполненных упражнениях.

Сервер слушает только `127.0.0.1`. Запросы изменения защищены локальным токеном и проверкой источника; разрешён фиксированный набор имён файлов. Компиляция ограничена 40 секундами, один тест — 8 секундами, вывод — 48 КБ. Команды запускаются массивом аргументов без shell; каждый запуск получает отдельную рабочую директорию со снимком решения. Это локальный тренажёр доверенного пользовательского кода, не изолированная ОС-песочница для враждебных программ.
